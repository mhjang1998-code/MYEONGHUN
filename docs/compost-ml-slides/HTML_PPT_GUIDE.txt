 1. 페이퍼로지 HTML PPT 스타일 해부 (motion-template.html 실제 코드 기준)
================================================================
[인상]
 - 흰 배경 + 클라인 블루(#002FA7) 한 가지 계열 + 오렌지는 포인트로만.
 - 둥근 모서리·그림자·그라데이션·이모지 없음. 각진 플랫 박스, 얇은 선.
 - 컨설팅 보고서 같은 정갈함 + 웹다운 모션/클릭 인터랙션.

[캔버스]
 - 1920x1080 고정 무대(#stage)를 화면 크기에 맞춰 scale (비율 유지, 남는 영역은 어두운 #161C20 레터박스).
 - 모든 요소 absolute 배치 -> 어떤 해상도에서도 레이아웃 안 깨짐.

[폰트]
 - Pretendard 400/500/700 (woff2를 base64로 HTML 안에 내장 -> 인터넷 없이도 폰트 유지).
 - word-break: keep-all (한글 단어 중간 줄바꿈 방지).
 - 숫자는 font-variant-numeric: tabular-nums.

[컬러 토큰]
 --main  #002FA7  (메인 블루: 섹션명, 큰 숫자, 버튼 테두리, 1순위 막대)
 --t1    #4D6DC1  (2순위 막대)
 --t2    #99ACDB  (3순위 막대, 기준값 막대)
 --t3    #D9E0F2  (연한 강조 배경)
 --panel #EAEEF8  (카드/사이드 패널 배경)
 --deep  #001C64  (진한 글자)
 --acc   #FF7A00  (오렌지: 포커스·클릭 표시에만 극소량)
 --gray  #B7BDC5 / --g0 #EEF0F2 / --rule #D0D6DE (회색 계열, 구분선)
 --ink   #222222  (본문)  /  --note #6B7C85 (주석·출처)
 이징: cubic-bezier(.22,.68,.18,1)

[고정 그리드 - 모든 장 동일 위치]
 - 좌우 여백 86px
 - 섹션명(챕터)  : top 62px, 28px, 700, 메인블루
 - 헤드라인(결론 문장): top 116px, 48px, 700, 한 줄, 자간 -0.02em
 - 서브타이틀    : top 223px, 24px, 700
 - 본문 시작     : top 279px
 - 주석(note)    : 하단 66px, 18px, 회색 (데이터 성격/전제)
 - 푸터          : 하단 24px, 좌측 출처·계산식 / 우측 "1 / 3" 쪽번호
 - 3단 그리드: 폭 556px, 간격 40px (x = 86, 682, 1278)
 - 큰 숫자: 88~96px 메인블루 + 단위는 32px 검정 small
 - 오른쪽 사이드 패널: x 1210, 폭 624, 배경 #EAEEF8, 큰 숫자 + 설명 + 항목별 표

[모션]
 - 요소 순차 등장: opacity 0 -> 1 + translateY(16px -> 0), 요소마다 지연값(0, 150, 400 ... 2200ms)
 - 막대 그래프 성장: scaleX(0 -> 1), 0.9s
 - 페이지 전환: 페이드 0.45s
 - 클릭 강조: 링(ring) 퍼지는 효과 1회

[인터랙션 (HTML PPT의 킥)]
 - "한 단계씩 따라가기" 버튼: 현재 단계만 진하게, 나머지는 opacity 0.25로 흐리게, 현재 카드 상단에 5px 블루 바 + 라벨 태그
 - 카드 클릭 -> 오른쪽에서 720px 서랍(drawer) 슬라이드 인 (탭: 내역 / 출처와 전제), 뒤는 반투명 스크림
 - 차트 보기 전환 토글: 같은 데이터를 막대 <-> 100칸 격자(와플)로 전환
 - 막대 hover 툴팁
 - 레버 시뮬레이터: 슬라이더 3개 조절 -> 기준값 vs 현재값 비교 막대, 큰 숫자, 증감, 계산식이 실시간 변경 + "기준값으로 초기화"
 - 키보드: ←/→/Space/PageUp/PageDown 이동, 숫자키 쪽 점프, O = 전체 쪽 목록, Esc = 닫기/뒤로, D = 자동 시연(가짜 커서가 돌아다니며 클릭)
 - 하단 "‹ 이전 / 쪽 목록 / 다음 ›" 작은 버튼
 - URL #2 로 특정 쪽 바로 열기, #static 또는 '동작 줄이기' 설정 시 애니메이션 끔

[구조 비법]
 - 내용은 <script type="application/json" id="presentation-data"> JSON 한 곳에만, 렌더링 엔진(JS)은 고정.
   -> 주제 바꿀 때 JSON만 수정. 디자인 붕괴 없음.
 - 글자 수 제한: 헤드라인 36자, 서브 65자, 주석 108자, 카드 라벨 25자, 차트 라벨 12자 등.
 - 정직성 규칙: 실제 통계가 없으면 "예시 데이터 · 입력에 따른 계산" 명시, 통계·논문·링크 지어내기 금지.

 2. 유튜브에서 모은 HTML PPT 꿀팁 25개
================================================================
[준비]
 1. 내용 먼저, 디자인은 나중. 글/대본이 완성돼야 좋은 슬라이드가 나옴. (페이퍼로지, 헤이디, Dylan Davis)
 2. 막히면 말로 풀어서 녹음 -> 전사 -> 개요로 정리. (신영선)
 3. "PPT 만들어줘" 한 줄은 망하는 지름길. 폰트·색상코드·비율·레퍼런스 4가지를 꼭 지정. (헤이디)
 4. 취향은 말이 아니라 보여주는 것. 레퍼런스 이미지 3~5장 + "Reference 1에서는 아이콘, 2에서는 데이터 표현"처럼 무엇을 참고할지 지정. (페이퍼로지, 헤이디)
 5. 디자인 설계도(design.md)를 먼저 만든다. getdesign.md에서 마음에 드는 회사 스타일을 복사 -> PPT용으로 수정. 디자인 프롬프트는 영어가 더 잘 먹힘. (페이퍼로지)
 6. 페이퍼로지 PPT 10원칙: 제목·부제·챕터명·쪽수·본문 항상 같은 자리 / 같은 폰트 크기 / 차트·그래프 최대한 / 폰트 하나(Pretendard) / 빈 공간 없이 밀도 / 제목은 결론 문장 / 16:9 / 레이아웃 단단하게 / 본문 하단 비우지 않기 / 출처 표기. (페이퍼로지)
 7. 폰트는 이름만 말하지 말고 파일 첨부 또는 CDN 링크 제공. HTML은 base64 내장하면 오프라인에서도 유지. (헤이디, 페이퍼로지 템플릿)

[제작]
 8. 처음부터 전체 X. 본문 1~2장만 먼저 만들어 기준 확정 -> 나머지 확장. (헤이디, 페이퍼로지, 진한별)
 9. 출력은 "단일 HTML 파일" 하나로. CSS·JS·폰트 전부 내장. (Dylan Davis, 페이퍼로지)
 10. 1920x1080 고정 무대 + 화면에 맞춰 축소. 웹페이지처럼 스크롤되는 결과는 실패. (쉬운AI, Slides by Sander)
 11. 텍스트는 줄이고 숫자는 그래프로, 줄글은 도식으로. (쉬운AI, 신영선, Dylan Davis)
 12. 슬라이드당 강조색 하나. 시선이 한 곳에 모이게. (Dylan Davis)
 13. 오른쪽 화살표/Enter를 누를 때마다 다음 요소가 나타나는 단계별 등장 -> 대본 흐름에 맞춰 설계. (쉬운AI, 헤이디)
 14. HTML만의 무기: hover 강조, 카드 펼치기, 상세 서랍, 차트 보기 전환, 레버 시뮬레이터, 목차 클릭 점프, 진행 막대. 발표 목적에 맞는 것만 골라 쓰기. (페이퍼로지, Sander, 헤이디)
 15. 레버 시뮬레이터는 상담·견적·비용 대비 효과 설명에 최강 (페이퍼로지: 성형외과 상담, 인테리어 견적, 회사 비용 분석 활용).
 16. 내용 데이터(JSON)와 디자인 엔진을 분리하면 주제만 바꿔 무한 재사용. (페이퍼로지 템플릿 구조)
 17. 웹사이트처럼 글자가 작아지면 "슬라이드 전체 공간을 쓰고 글자를 키워라"고 수정 요청. (Slides by Sander)

[수정·검증]
 18. 수정 요청은 구체적으로: "부제목 20px 위로, 본문 10px 위로, 로고와 쪽번호 위치 교체". 말로 안 되면 직접 고친 화면을 같이 첨부. (페이퍼로지)
 19. 수정할 때도 원래 레퍼런스를 다시 첨부. 빼면 AI가 스타일을 슬쩍 바꿈. (헤이디)
 20. 수정사항은 모아서 한 번에. 작은 수정은 빠른 모델, 구조 변경은 상위 모델. (Dylan Davis)
 21. AI 게으름 대책: 여러 장 만들수록 비슷한 형식 반복 -> 도식화 풍부한 1차 레퍼런스(구조안)를 먼저 주고 마무리만 맡기기. (페이퍼로지)
 22. 할루시네이션은 다른 AI에게 검증시킴. 숫자·월·기준연도·출처 교차검증. (페이퍼로지)
 23. 겹침, 잘림, 단어 중간 줄바꿈, 큰 여백, 그래프 값-라벨 불일치를 체크리스트로 점검. 1366x768 / 1920x1080 / 2560x1440 확인. (헤이디, 장피엠, 페이퍼로지)

[재사용·공유]
 24. 완성된 프롬프트는 Claude 프로젝트 지침 / ChatGPT GPTs / Gemini Gems / Genspark 스킬로 박제. 스타일별로 프로젝트 여러 개. (페이퍼로지, 진한별, 신영선)
 25. 공유: HTML 파일 그대로 전송(크롬 더블클릭), Genspark 링크 공유, GitHub Pages(index.html). 단, PDF로 바꾸면 애니메이션 사라지고, 회사 보안상 HTML 첨부가 막힐 수 있음. 자주 고쳐야 하는 문서는 PPTX가 나을 수도. (헤이디, Dylan Davis, 페이퍼로지)

 P1. 마스터 프롬프트 - 페이퍼로지 스타일로 처음부터 만들기 (메인)
----------------------------------------------------------------
▼▼▼ 여기부터 복사 ▼▼▼

주제: [발표 주제 한 줄]
청중/목적: [예: 연구실 랩미팅 / 과제 중간보고 / 고객 상담 - 무엇을 결정하게 할지]
분량: [N]장
내용: [아래에 원고, 대본, 개요, 데이터 붙여넣기. 첨부 파일이 있으면 "첨부 파일 기준"이라고 적기]

위 내용으로 브라우저에서 바로 발표하는 HTML 프레젠테이션을 "단일 HTML 파일(presentation.html)" 하나로 완성해줘. 질문이나 개요 제안에서 멈추지 말고 실제 작동하는 파일을 줘.

[1. 캔버스·구조]
- 1920x1080 고정 무대(#stage)를 만들고 창 크기에 맞춰 비율 유지 scale. 남는 영역은 #161C20 레터박스. 스크롤 금지.
- 모든 장은 .page로 겹쳐 두고 현재 장만 표시. 요소는 고정 좌표 배치로 해상도가 바뀌어도 레이아웃이 절대 무너지지 않게.
- 슬라이드 내용은 <script type="application/json" id="presentation-data"> 한 곳에 JSON으로 두고, JS가 그걸 읽어 화면을 그리게 해. (나중에 JSON만 고치면 내용 수정 가능)
- 외부 라이브러리 없이 순수 HTML/CSS/JS + 인라인 SVG로 차트 작성.

[2. 폰트]
- Pretendard만 사용 (400/500/700). CDN: https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css
  (가능하면 woff2를 base64로 내장해서 오프라인에서도 유지. 불가하면 CDN + sans-serif 대체)
- word-break: keep-all, 숫자는 tabular-nums, 헤드라인 자간 -0.02em.

[3. 컬러 (이 외 색 금지)]
- 메인 #002FA7 / 단계색 #4D6DC1, #99ACDB, #D9E0F2 / 패널 배경 #EAEEF8 / 진한 글자 #001C64
- 본문 #222222 / 주석 #6B7C85 / 구분선 #D0D6DE / 회색 #B7BDC5, #EEF0F2
- 오렌지 #FF7A00은 포커스·클릭 표시용으로만 아주 조금.
- 흰 배경. 둥근 모서리, 그림자, 그라데이션, 이모지, 장식용 아이콘 금지. 각진 플랫 박스와 1~1.5px 선만.

[4. 고정 그리드 - 모든 장 같은 위치·같은 크기]
- 좌우 여백 86px.
- 섹션명(챕터): top 62px, 28px, bold, #002FA7
- 헤드라인: top 116px, 48px, bold, 한 줄. 반드시 그 장의 "결론 문장"으로 (36자 이내).
- 서브타이틀: top 223px, 24px, bold (65자 이내).
- 본문 영역: top 279px ~ 하단 110px. 하단을 비워두지 말고 밀도 있게 채우되 겹치지 않게.
- 주석: 하단 66px, 18px, #6B7C85 - 데이터 성격·전제·주의사항 한 줄.
- 푸터: 하단 24px, 왼쪽 출처/계산식, 오른쪽 "현재쪽 / 전체쪽".
- 3단 그리드: 폭 556px, 간격 40px (x=86, 682, 1278). 2단은 좌측 본문(약 1060px) + 우측 사이드 패널(x=1210, 폭 624, 배경 #EAEEF8).
- 핵심 숫자: 88~96px bold #002FA7 + 단위는 32px #222 작은 글씨.
- 본문 글자 최소 18px, 일반 20px.

[5. 장별 구성 원칙]
- 한 장에 메시지 하나. 텍스트는 짧게, 자세한 전제·근거·표는 클릭하면 열리는 "서랍"에.
- 숫자·비율은 무조건 차트(막대/100칸 격자/비교 막대/타임라인 띠), 과정은 단계 카드+화살표, 비교는 표나 좌우 대비로 도식화. 줄글 나열 금지.
- 장 유형을 섞어서 단조롭지 않게: 핵심 숫자 3카드 / 단계 흐름 / 같은 데이터 2가지 차트 보기 / 비교표+사이드 요약 / 레버 시뮬레이터 / 결론·다음 할 일.
- 표지는 큰 제목 + 부제 + 발표자/날짜만 간결하게. 마지막 장은 결론 3줄 + 다음 액션.

[6. 모션]
- 요소 순차 등장: opacity 0->1 + translateY(16px->0), 0.5~0.7s, easing cubic-bezier(.22,.68,.18,1). 요소마다 지연(헤더 0ms -> 본문 150~400ms -> 카드 60ms 간격 -> 하단 버튼 마지막).
- 막대 그래프는 scaleX(0->1)로 0.9s 성장. 숫자는 카운트업 가능.
- 페이지 전환 페이드 0.45s. 과한 회전·바운스·글로우 금지.
- URL에 #static이 있거나 prefers-reduced-motion이면 애니메이션 끄고 즉시 표시.

[7. 인터랙션]
- 키보드: →/Space/PageDown 다음, ←/PageUp 이전, 숫자키 해당 장 이동, O 전체 쪽 목록(썸네일 그리드, 클릭 이동), Esc 닫기/뒤로.

8. 모든 장의 섹션명·헤드라인·서브·쪽번호 위치와 크기가 완전히 같은지 다시 맞춰.
수정 후 변경한 장 번호와 변경 내용만 짧게 알려줘.

(말로 설명이 어려우면: "첨부 1은 네가 만든 것, 첨부 2는 내가 직접 고친 것. 첨부 2처럼 나오게 고쳐줘" + 스크린샷 2장 첨부)

▲▲▲ 여기까지 복사 ▲▲▲


----------------------------------------------------------------
 P6. 레퍼런스 이미지 -> 스타일 프롬프트 추출 (ChatGPT/Claude에 이미지와 함께)
----------------------------------------------------------------
▼▼▼ 여기부터 복사 ▼▼▼

첨부한 이미지의 디자인 스타일로 HTML 발표 슬라이드를 만들고 싶어. 내용 말고 디자인만 참고할 거야. 내용은 따로 있어.
이 스타일을 AI가 그대로 재현할 수 있도록 영어 디자인 시스템 프롬프트로 정리해줘:
- color tokens (HEX), typography (font, sizes, weights, letter-spacing), grid & margins (px on a 1920x1080 canvas),
- component styles (cards, buttons, charts, tables, dividers), chart styling, iconography, imagery rules,
- motion style, and a "do / don't" list.
마지막에 한 줄로 요약한 스타일 이름도 붙여줘.

▲▲▲ 여기까지 복사 ▲▲▲
 * 결과물을 P1의 [3. 컬러]~[4. 고정 그리드] 자리에 바꿔 끼우면 다른 스타일 버전 완성.
 * 레퍼런스 찾는 곳: behance.net, getdesign.md (페이퍼로지 추천).


----------------------------------------------------------------
 P7. 기존 PDF/PPT/논문 -> HTML PPT 리디자인
----------------------------------------------------------------
▼▼▼ 여기부터 복사 ▼▼▼

첨부한 [PDF/PPT/논문/보고서]를 위 디자인 규칙(P1)의 HTML 프레젠테이션으로 다시 만들어줘.
- 원본의 내용·수치·출처는 바꾸지 말고, 표현만 재구성.
- 원본 1장 = HTML 1장으로 옮기지 말고, 메시지 단위로 [N]장 내외로 재구성.
- 원본의 표·그래프 수치는 HTML 차트(인라인 SVG)로 다시 그리고, 원본 표는 클릭 서랍에 넣어.
- 원본에서 읽을 수 없는 숫자는 추정하지 말고 "[원본 확인 필요]"로 표시.
- 마지막에 원본 페이지 -> HTML 장 대응표를 짧게 줘.

▲▲▲ 여기까지 복사 ▲▲▲


----------------------------------------------------------------
 P8. 팩트·숫자 교차검증 프롬프트 (가능하면 만든 AI와 "다른" AI에게)
----------------------------------------------------------------
▼▼▼ 여기부터 복사 ▼▼▼

첨부한 HTML 발표 파일과 원본 자료를 대조해서 오류만 찾아줘. 고치지 말고 목록으로만.
점검 항목:
1. 수치·단위·기준연도·월 표기가 원본과 다른 곳
2. 차트 막대 길이/비율과 라벨 숫자가 안 맞는 곳, 합계·구성비 계산 오류
3. 원본에 없는 통계·출처·링크·효과 주장 (지어낸 내용)
4. 헤드라인 결론이 본문 근거로 뒷받침되지 않는 곳
5. 오탈자, 띄어쓰기, 같은 용어의 표기 불일치
형식: 장 번호 | 위치 | 문제 | 원본 근거 | 수정 제안
확실하지 않은 지적은 "추정"이라고 표시.

▲▲▲ 여기까지 복사 ▲▲▲


----------------------------------------------------------------
 P9. 인쇄/PDF 저장 대응 추가 프롬프트 (선택)
----------------------------------------------------------------
▼▼▼ 여기부터 복사 ▼▼▼

이 HTML에 인쇄용 모드를 추가해줘. 화면 발표 기능은 그대로 유지.
- @media print 와 URL #print 에서: 모든 장을 순서대로 펼쳐 1장 = 1페이지(1920x1080, @page size 1920px 1080px, margin 0)로 출력.
- 애니메이션 끄고 모든 요소 최종 상태로 표시, 버튼·스크림·커서 숨김, 차트는 기본 보기.
- 서랍 내용은 별도 부록 페이지로 마지막에 출력.
크롬에서 Ctrl+P > PDF로 저장 > 배경 그래픽 체크로 저장하면 되게.

----------------------------------------------------------------
 P10. 프로젝트 지침/스킬 등록용 짧은 버전
      (Claude 프로젝트 지침, ChatGPT GPTs, Gemini Gems, Genspark 스킬에 넣어두기)
----------------------------------------------------------------
▼▼▼ 여기부터 복사 ▼▼▼

You create Korean presentation decks as ONE self-contained HTML file (presentation.html). Never stop at an outline; deliver a working file.

CANVAS: fixed 1920x1080 #stage scaled to fit the window (letterbox #161C20), no scrolling, absolute positioning so layout never breaks. Slide content lives in <script type="application/json" id="presentation-data">; JS renders it. Pure HTML/CSS/JS + inline SVG charts, no external libraries.

TYPE: Pretendard only (400/500/700; embed woff2 as base64 when possible, else jsDelivr CDN). word-break: keep-all; tabular-nums for numbers; headline letter-spacing -0.02em.

COLOR (no others): main #002FA7, steps #4D6DC1 #99ACDB #D9E0F2, panel #EAEEF8, deep #001C64, ink #222, note #6B7C85, rule #D0D6DE, gray #B7BDC5 #EEF0F2, accent #FF7A00 for focus only. White background. No rounded corners, shadows, gradients, emojis or decorative icons; flat square boxes and 1–1.5px lines.

GRID (identical on every slide): side margin 86px; section label top 62px 28px bold main; headline top 116px 48px bold one line = the slide's conclusion (≤36 Korean chars); subtitle top 223px 24px bold; body from 279px to bottom 110px, dense but no overlap; note bottom 66px 18px gray; footer bottom 24px (source left, "n / N" right). 3 columns: width 556, gap 40 (x 86/682/1278). 2-column: body ~1060px + side panel x1210 w624 bg #EAEEF8. Key numbers 88–96px bold main with 32px unit. Body text ≥18px (normal 20px).

CONTENT: one message per slide; numbers become charts, processes become step cards with arrows, comparisons become tables. Short on-screen text; details, tables and sources go in a click-open right drawer. Mix slide types (3 KPI cards, step flow, same data in bar vs 100-cell composition toggle, comparison + side summary, 3-lever simulator, conclusion + next actions).

MOTION: staggered reveal (opacity + translateY 16px, 0.5–0.7s, cubic-bezier(.22,.68,.18,1)), bars grow scaleX 0.9s, page fade 0.45s. #static or prefers-reduced-motion disables motion.

INTERACTION: ←/→/Space/PageUp/PageDown, number keys jump, O overview grid, Esc close/back; small "‹ 이전 / 쪽 목록 / 다음 ›" buttons; "한 단계씩 따라가기" step focus (others opacity .25, active card gets 5px top bar); "내역 보기 ›" opens 720px right drawer with tabs 내역 / 출처와 전제 over rgba(10,16,24,.35) scrim; chart hover tooltips; optional lever simulator (3 sliders → baseline vs current bars, big result, delta, formula, reset; only multiplicative/linear formulas, sensible at min/max); #N hash deep links. Buttons: white, 1.5px main border, invert on hover.

HONESTY: never invent statistics, papers, links or effects. Mark illustrative numbers as "예시 데이터 · 입력에 따른 계산". Same unit/denominator within a chart; verify totals and percentages.

CHECK BEFORE DELIVERY: no clipping/overlap/mid-word breaks/two-line headlines at 1366x768, 1920x1080, 2560x1440; all keys, buttons, drawers, toggles, levers work; no console errors; bar lengths match labels. State anything you could not verify. Final reply: file + what was actually checked, briefly.

▲▲▲ 여기까지 복사 ▲▲▲
 * 디자인 지시는 영어가 더 잘 먹힌다는 페이퍼로지 팁 반영해 영어로 작성. 사용할 때는 "주제: ..., 내용: ..."만 한국어로 던지면 됨.


================================================================
 4. 발표·공유 방법
================================================================
 - 발표: HTML 더블클릭 -> 크롬에서 열림 -> F11 전체화면 -> 방향키/스페이스로 진행. D키 자동 시연(페이퍼로지 템플릿).
 - 파일 공유: HTML 파일 하나만 보내면 됨 (폰트 내장 시 인터넷 없어도 동일하게 보임).
 - 링크 공유: Genspark 결과 > Share > Just Slides > 누구에게나 링크 공유 (수정하면 실시간 반영) / GitHub Pages에 index.html로 올려 URL 공유.
 - PDF 필요 시: P9 적용 후 크롬 Ctrl+P -> PDF 저장 (애니메이션·인터랙션은 사라짐).
 - 주의: 회사·기관 메일에서 HTML 첨부가 차단될 수 있음 -> zip 압축 또는 링크 공유. 수정이 잦은 결재 문서는 PPTX가 나을 수 있음.
 - 활용 아이디어: 상담(레버로 조건 바꾸면 추천 결과 변경), 견적, 비용 대비 효과, 연구 시나리오 비교(예: 처리 조건별 결과 시뮬레이션), 과제 진도 보고.
